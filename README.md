# Temple Aviv Judea

Astro website for Temple Aviv Judea, a Messianic Jewish congregation in Fullerton, California.

## Local development

```sh
pnpm install --frozen-lockfile
pnpm run dev
```

Use Node 24, which is pinned in `.node-version`. Install pnpm 11 if it is not already available; the repository pins the exact pnpm version in `package.json`. Its architecture settings install the native and WASM packages required by Astro's local and Cloudflare renderers.

To run the local TinaCMS editor without a TinaCloud account:

```sh
pnpm run dev:cms
```

Open the URL printed by Tina, then visit `/admin/`. Local CMS mode reads and writes the JSON content files in this repository.

## Verification

```sh
pnpm run validate:content
pnpm run check
pnpm run build
pnpm run build:cms:local
pnpm run build:cloudflare
pnpm audit --prod
pnpm exec wrangler deploy --dry-run
```

## Deployment

The canonical production site is:

`https://www.avivjudea.org/`

Cloudflare Workers Builds is linked directly to
`Skarath13/temple-aviv-judea`. Every push to `main` runs
`pnpm run build:cloudflare` and `pnpm exec wrangler deploy` in Cloudflare. This
native Git integration is the primary production deployment path; there is no
GitHub Actions Worker deployment workflow.

GitHub Actions still publishes the static build to
`https://skarath13.github.io/temple-aviv-judea/` as a rollback aid. It is not
the canonical production host. The default build remains compatible with that
base path; Cloudflare/Tina mode uses the Cloudflare adapter and a root base path.
`www` is a Worker Custom Domain and the apex redirects canonically to it while
preserving path and query. Exact DNS, MX, and Wix rollback records are in
`AGENTS.md`.

The native Cloudflare build configuration requires:

- `PUBLIC_TINA_CLIENT_ID`
- encrypted `TINA_TOKEN`
- `SITE_URL=https://www.avivjudea.org`
- `NODE_OPTIONS=--max-old-space-size=4096`

Cloudflare injects `WORKERS_CI_BRANCH`. The dedicated Cloudflare-generated build
token performs the deployment. Do not replace it with a broad account API token
or commit any secret value.

## TinaCMS content model

The selected CMS is TinaCMS, with TinaCloud providing hosted authentication,
the content API, media synchronization, and Git publishing.

- Site identity, contact details, service times, links, and navigation: `src/content/settings/site.json`
- Every public page's SEO, hero, designed body content, images, accessible descriptions, links, and optional page-builder sections: `src/content/pages/*.json`
- Up to three homepage events: `src/content/events/events.json`
- Tina schema and editor controls: `tina/`
- Media managed through Tina: `public/images/`

The schema provides a page-specific, no-code editor for every existing designed section while keeping the route structure, styling, payment mechanics, and component templates developer-controlled. The Cloudflare-mode build also wires Tina's Astro island route and click-to-edit field markers for visual page editing.

The public GitHub Pages build uses `/admin-preview/` for the nonfunctional CMS explanation. In Tina and Cloudflare mode, `/admin/` is reserved for the real editor generated by Tina.

## TinaCloud and Cloudflare Workers operations

The TinaCloud project, Worker, persistent `SESSION` KV binding, production
Custom Domain, and canonical redirects are active. The remaining hosted
acceptance work is:

1. Perform two intentional Tina saves and verify each save creates the expected
   `main` commit, native Cloudflare build, Worker version, and live change.
2. Test an approved Editor or backup collaborator and an unauthorized account.
3. Test real media upload, replacement, and deletion.
4. Rotate the setup-era Cloudflare account token and R2/S3 credential, then
   remove the unrelated credential variables from the local `.env`.

The local variable names are documented in `.env.example`. `wrangler.jsonc`
enables `nodejs_compat` and pins the production `SESSION` KV namespace. Custom
Domains and DNS redirects remain dashboard-managed.

Tina content is Git-backed. Cloudflare D1 and R2 are not required for ordinary page editing. Reserve those services for future runtime application data that does not belong in versioned site content.
